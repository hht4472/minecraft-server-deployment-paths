## 路径一：自己电脑 + Fabric + 内网穿透，0 元

这条路的教程作者用的示例环境是 Windows 11 24H2 专业版 x64、i7-13650HX、Minecraft 1.21.5、Fabric 0.16.13，只适用于 x86 架构的 Windows。AMD 平台同样可以，Apple 芯片的 Mac 不行。

**准备两样东西**：JDK 21 的 Windows x64 安装程序，以及 Fabric 安装器。JDK 版本要跟着 MC 版本走，1.21 系要 JDK 21，具体版本对应关系装之前查一下。

**搭建流程**：

1. 建一个服务器文件夹，名字好记就行。
2. 运行 Fabric 安装器，选「服务端」，指定安装版本和安装路径，定位到刚才那个文件夹。
3. 提示找不到有效服务端时，点「下载服务端」。
4. 提示已找到有效服务端后，点「生成」生成启动脚本，关闭安装器。
5. 双击 `start.bat`。控制台弹出报错就关掉，打开文件夹里新生成的 `eula.txt`，把 `false` 改成 `true`，保存。
6. 再次运行 `start.bat`，控制台出现 `Done` 字样，服务器就起来了。

关服在控制台输入 `stop` 回车，别直接关窗口。

**配置文件 `server.properties`** 里两项最关键：

- `online-mode` 决定是否校验正版登录。让用第三方启动器离线登录的朋友能进来，得把它改成 `false`，代价是任何人都能冒用任意 ID 进服，服务器安全性下降。自己人小圈子玩可以接受，公开服别关。
- `level-name` 指定世界文件夹名。想换存档，删掉原来的 `world` 文件夹，把新存档拖进来改名 `world`，或者直接把 `level-name` 改成新文件夹的名字。

`mods` 文件夹没有就手动建一个。**Fabric API 必须放进去**，缺了它，其他模组一律不生效。

**内网穿透**用 MossFRP：注册登录，下载 Java 版客户端，先去「服务 > 节点状态」看哪个节点可用，再到「穿透码列表」创建穿透码，选节点、带宽和天数。参考值是 3 名玩家约消耗 1Mbps 带宽，创建时间最低 3 天，消耗银币或金币（每日签到或充值获得）。客户端里依次输入 `save 1 你的穿透码` 建隧道、`reload` 生效，就会给出一个连接地址，朋友在多人游戏里添加这个地址即可。`exit` 停止穿透。

这条路的短板很明确：电脑关机服务器就没了，家里上传带宽也扛不住人多。

## 路径二：云服务器 + MCSManager 面板，最主流

MCSManager 是开源、可分布式部署的游戏服务器控制面板，支持 Minecraft 和 Steam 系服务端，带多用户权限系统，能同时管多台机器。前排教程大多集中在这条路上，因为它把开服变成了点鼠标。

**系统选择**：Ubuntu 22.04 LTS 或 24.04 LTS、Debian 12 都可以。CentOS 7 装不了，安装时会直接提示「操作系统版本过低，无法使用」。习惯纯命令行的话 CentOS 7 还能用来手工跑服务端，但用不了面板。

**安装**（必须 root）：

bash
sudo su -c "wget -qO- https://script.mcsmanager.com/setup_cn.sh | bash"


装完访问 `http://服务器IP:23333/`，按提示设置账号密码，再去「节点」里把远程节点 IP 和端口 24444 填好。**23333 是面板端口，24444 是节点端口，25565 是 MC 默认端口，三个都要在云厂商安全组里放行**，少放一个就连不上。

**建实例**。启动命令以 Paper 1.21 为例：

bash
java -server -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar paper-1.21-50.jar


`-Xms128M` 是初始堆内存，`-XX:MaxRAMPercentage=95.0` 允许 JVM 用掉系统可用内存的 95%，`-Dfile.encoding=UTF-8` 防中文乱码，`-Duser.country=CN` 让部分服务端走中文和国内镜像下载资源。

首次启动前，在面板的「服务端配置文件」里把 `eula.txt` 的 `false` 改成 `true`，再点开启。控制台出现 `Done` 就成功了。要关正版验证或改端口，编辑 `server.properties` 后重启实例。

面板提供的能力包括服务端配置文件编辑、文件管理、事件任务、应用实例设置，换地图和传模组直接在文件管理里操作，比手工敲命令省事。

## 路径三：Ubuntu + Paper 手工部署，或 Docker 一条命令

不想装面板，Ubuntu 22.04 LTS 上手工跑 Paper 也就几步：

bash
wget https://papermc.io/api/v2/projects/paper/versions/1.19/builds/477/downloads/paper-1.19-477.jar -O paper.jar


链接里的版本号和 build 号会随更新变化，下载前先去官网确认当前版本。然后写启动脚本 `start.sh`：

bash
#!/bin/bash
java -Xmx7G -Xms7G -jar paper.jar nogui


`chmod +x start.sh` 后 `./start.sh`。首次启动会生成 `server.properties` 和 `eula.txt`，把 `eula=false` 改成 `eula=true`，再启动一次。`server.properties` 里可以设 `server-name`、`server-port=25565`、`motd`。

熟 Docker 的人有更快的方式，`itzg/minecraft-server` 镜像：

yaml
services:
  mc:
    image: itzg/minecraft-server
    ports:
      - "25565:25565"
    environment:
      - EULA=true
      - VERSION=1.20.4
      - MEMORY=2G
    volumes:
      - ./data:/data


`docker compose up -d` 之后世界生成完服务会自己停一次，日志里看到 `Stopping server...` 就 `docker compose restart`，之后正常在线。注意示例里的 `VERSION=1.20.4` 和 `MEMORY=2G` 是演示值，不代表推荐值，尤其 2G 内存跑现代模组服会直接 OOM。

## 服务端类型：装错版本，后面全白费

| 服务端 | 能做什么 | 适合谁 | 注意 |
| --- | --- | --- | --- |
| 原版 | 官方服务端，无任何修改 | 只想原汁原味联机 | 不能加模组 |
| Forge | 模组加载器与 API，模组生态最大 | 要装大量模组 | 1.21 需先跑 `-installServer` 安装，再改 `user_jvm_args.txt` 里的 `-Xmx` 和启动命令 |
| Fabric | 更轻量，跟进新版本快 | 想用最新 MC 版本、偏开发向 | 必须放 Fabric API 做前置 |
| Paper | Spigot 的高性能分支，兼容大部分 Bukkit/Spigot 插件 | 要性能和稳定性、跑插件服 | 不适合装 Forge 模组 |
| Mohist | 融合 Forge 与 Bukkit/Spigot，模组和插件能同时跑 | 既想装模组又想装插件 | 目前只更新到 1.20.2 |

模组有个规则容易踩：模组分服务端模组和客户端模组。服务端模组（比如连锁采集）必须本地和服务器都装，而且版本完全一致；客户端模组（比如小地图）只在本地装就行，传不传服务器都能用。保险做法是本地 `mods` 和服务器 `mods` 保持一份完全相同的清单。

## 配置和带宽：按人数和模组分档，别记一个绝对数字

网上流传的「最低配置」差得很远，原因不是谁写错了，是场景不同。

| 场景 | CPU | 内存 | 带宽参考 |
| --- | --- | --- | --- |
| 2–5 人原版或轻量 Fabric | 2 核起 | 4G 起 | 十兆级别够用 |
| 10–15 人插件服 | 4 核 | 8G | 10Mbps 以上 |
| 重度模组整合包（ATM10 一类） | 4–6 核，主频越高越好 | 10G 以上 | 10Mbps |

三条口径分别来自不同教程：一份面向多服务端高频场景的教程写「最低不要低于 4 核 8G」，并强调「高版本 Java 服很吃单核性能和内存」；一份 Ubuntu + Paper 教程写「CPU 至少 2 核、内存至少 4GB、带宽至少 10Mbps」，并给新手推荐 4 核 8G 可支持 10–15 人；一份基于轻量云服务器的实操写「2 核 4G 以上、带宽 5Mbps 以上」，同时提醒轻量套餐单核性能有限。

带宽的估算也有两个口径：Windows 免费穿透方案给的是「3 名玩家约 1Mbps」，模组整合包教程给的是「1Mbps 可带约 2 人」。前者针对轻量原版或小型 Fabric 服，后者针对带模组、区块加载压力大的场景，两个数字放在一起看就是 1Mbps 对应 2–3 人，模组越多取小值。

MC 的 Java 引擎对多核利用率有限，**决定 TPS 的是单核主频，核心数次要**。这是很多人配服务器时最容易搞反的一点：8 核 2.4GHz 跑模组服，往往不如 4 核 5.0GHz。挑机器时先看 CPU 型号的主频，再核数量。

## 五个高频坑

**1. JDK 版本跟 MC 版本走。** 1.21 系要 JDK 21，几份 1.21 的教程用的都是 JDK 21 装包。网上有些教程写 `sudo apt install openjdk-17-jdk`，那是因为它们演示的是 1.19 服务端，套到 1.21 上会起不来。

**2. CentOS 7 装不了 MCSManager。** 安装脚本会直接报系统版本过低。换 Ubuntu 24.04 LTS、Debian 12 或 CentOS 8 以上。

**3. 换存档后权限不对，服务端起不来。** 如果服务是以非 root 用户（比如 `mcfabricuser`）跑的，替换 `world` 文件夹后要重新授权：`sudo chown -R mcfabricuser:mcfabricuser /minecraft`，否则新用户写不进去。

**4. 端口只放了一个。** MCSM 要 23333 和 24444，MC 要 25565。云厂商安全组和系统防火墙是两道门，都要开。有的教程图省事直接 `systemctl stop firewalld` 全关，其实只开放需要的端口更安全。

**5. `online-mode` 改成 `false` 有代价。** 这一项关掉的是正版登录校验，方便离线客户端进来，同时任何人都能顶着别人的 ID 进服。只在自己人圈子里关，公开服保持默认。

顺带一句合规：MC 服务器属于网络游戏服务，按相关规定不得开设私服做盈利性运营，朋友之间自己玩没问题。
